# Модуль GraboSku (каталог производителя Grabo)

## Описание модуля

Модуль хранит карточки товаров с сайта производителя Grabo (grabo-balloons.com) и поддерживает их в актуальном состоянии. Это не SKU конкурента и не срезы остатков: отдельная коллекция `graboskus`, которую наполняет полный обход каталога (sitemap → категории → карточки).

Задачи модуля:

- создать карточку, если артикул производителя появился на сайте;
- обновить поля, если карточка уже есть;
- пометить `isOnSite: false`, если URL больше не встречается в листингах успешного прогона;
- отдать Excel со всеми полями модели (кроме mongo id) для фронта;
- отдать пагинированный каталог фронту с фильтрами и, по запросу, полный набор опций селектов из всей коллекции.

Парсинг HTML живёт в `browser/grabo`. Этот модуль — хранение, оркестрация среза, cron и HTTP.

## Сущности

### GraboSku

Документ каталога производителя. Уникальность — `productId` (артикул с страницы товара, например `G72274`). Документы не удаляются.

Поля контракта карточки (имена как в `GraboSkuData`, кроме новинки):

- `title`, `productId`, `isNewProduct`, `color`, `size`, `material`, `gas`, `language`, `gasCapacity`, `tags[]`, `images[]`

Строковые атрибуты карточки допускают пустую строку: на сайте поле может отсутствовать, парсер пишет `""`. В схеме они не `required`, иначе Mongoose считает `""` отсутствием значения и валит upsert.

`isNewProduct` — новинка с PDP. В парсере (`GraboSkuData`) поле называется `isNew`; в Mongo/Excel — `isNewProduct`, потому что `isNew` у Mongoose reserved (`Document.isNew`) и ломает timestamps. Upsert мапит `isNew` → `isNewProduct`.

`tags` — массив тегов. На сайте и в парсере поле называется `tag` (`.attribute-tag1`); в Mongo/Excel — `tags`. Upsert мапит `tag` → `tags`.

Операционные поля:

- `url` — канонический URL страницы товара, по которому товар нашли в листинге;
- `isOnSite` — видели ли этот URL в листингах последнего **успешного** полного прогона;
- `lastSeenAt` — когда карточку успешно спарсили с PDP;
- `createdAt`, `updatedAt` — timestamps MongoDB.

## Связи

Модуль не ссылается на `Sku` / `Skugr` / срезы конкурентов. HTML и fetch — через `browser/grabo` (`fetchPageHtml` с `konkName: grabo`). Отчёт о завершении среза уходит в тот же канал analytics-уведомлений, что и остальные cron-задачи.

## Концепции и принятые решения

### Обход каталога

Источник категорий — HTML sitemap `/en/sitemap`, только дерево Products (`.site-map li.nav900`), плюс ручной список листингов, которых в sitemap нет (Maverick tableware: plates, napkins, banner, paper-cups). Extras мержатся после sitemap с дедупом: если URL уже есть в дереве Products, повторно не обходим. Каждая категория пагинируется по `nav.archive-links.pages a[rel="next"]`. Ссылка `rel="last"` на сайте Grabo может указывать не на фактическую последнюю страницу, поэтому её не используем.

URL карточек дедуплицируются: один товар в нескольких категориях даёт одну запись.

### Upsert по `productId`

Повторный срез обновляет атрибуты и `url`. Если fetch конкретной карточки упал, документ не трогаем: `isOnSite` и поля остаются как были.

### Absent-pass

`isOnSite: false` выставляется только если:

- sitemap и все категории отработали без ошибок;
- в прогоне есть хотя бы один listing-URL;
- `url` документа **не** входит в множество URL этого прогона.

Ошибка одной категории отменяет absent-pass целиком, чтобы не пометить «пропавшими» товары непройденной ветки.

### Темп запросов

Между страницами листинга, категориями и карточками — jitter 2500–7000 мс. Параллелизма нет. Один GET при ETIMEDOUT/сбросе сокета повторяется на том же URL (паузы 8 с, затем 20 с, затем 45 с в константах; три попытки). Если страница листинга так и не открылась — категория помечается failed, absent-pass не запускается.

### Ручной и регулярный срез

Один in-memory lock на процесс. Повторный запуск, пока идёт прогон — отказ. HTTP-триггер отвечает сразу (долгий обход не держит соединение). Cron — суббота 04:00 Europe/Kyiv.

### Каталог для фронта

Список отдаёт страницу документов и при флаге `includeFilterOptions` — уникальные значения `color`, `size`, `material`, `gas`, `language`, `gasCapacity`, `tags` из всей коллекции. Опции не зависят от текущих фильтров и текущей страницы: селекты заполняются один раз при первой загрузке. Для `size` в селекте живёт только префикс до `/` (дюймовая часть с PDP), потому что полные строки `40" / … cm` плодят дубли одной и той же опции. Фильтр по size матчит документы с этим префиксом, а не exact сырого поля. Query-фильтр тега — `tag` (один элемент массива `tags`); опции селекта — полный уникальный список `tags`.
