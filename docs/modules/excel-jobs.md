# Модуль Excel Jobs

## Назначение

Модуль убирает сборку XLSX с HTTP-потока Node. Раньше каждый Excel-эндпоинт держал запрос открытым и на main thread делал ExcelJS `writeBuffer`: при большом отчёте по продажам замирал весь процесс, включая параллельные запросы других пользователей. JSON для графиков ходил в те же агрегаты Mongo, но не строил книгу — поэтому графики не замерзали.

Excel-job — это отложенная выгрузка одного файла. Пользователь ставит задачу, сервер готовит файл в отдельном worker isolate, клиент смотрит прогресс подготовки, затем скачивает уже готовый файл обычным HTTP-download с `Content-Length`.

## Сущности и связи

**ExcelJob** — документ в Mongo: кто заказал (`userId`), какой отчёт (`kind`), сырые `params` как прислал клиент, статус жизненного цикла, фаза подготовки, прогресс 0–100, путь и имя готового файла, ошибка, `expiresAt`.

Связи: job принадлежит пользователю JWT; `kind` указывает на реестр отчётов, который валидирует params теми же Zod-схемами, что были у старых Excel-роутов, и вызывает прежние util/builder (sku-reporting, analog-slices, arts/poses/zones/grabo). Сами builders не знают про HTTP.

**Очередь** — in-process, один активный worker. Второй Excel не стартует, пока первый не закончил. Это защита CPU, не брокер вроде Redis.

**Worker** — `worker_threads` с отдельным V8 isolate и своим подключением к Mongo. ExcelJS и плотные циклы по SKU/дням живут там. HTTP-процесс только пишет статус в Mongo и стримит готовый файл с диска.

**Файл** — временный `.xlsx` в каталоге temp. После статуса `ready` живёт ограниченное время (`expiresAt`), затем job становится `expired` и файл удаляется.

## Статусы и фазы

Статусы: `queued` → `running` → `ready` | `failed` | `cancelled`; отдельно `expired`.

Фазы для UI подготовки: `queued`, `loading` (чтение Mongo), `building` (ячейки/ZIP), `finalizing` (запись на диск).

Прогресс — ориентир для UI, не гарантия линейности. Для больших SKU-отчётов builders шлют `onProgress` по блокам строк.

## Решения

- Без Redis/Bull: один процесс сервера, очередь в памяти, состояние в Mongo. Рестарт во время `running` помечает job failed и заново ставит `queued`.
- Скачивание не через `fetch().blob()`: файл уже на диске, отдача с `Content-Length` даёт нативный прогресс браузера. JWT в query не кладётся — короткий download-token с `typ=excel-dl`.
- Старые Excel GET/POST сохранены как 410 с `kind`, чтобы фронт мог мигрировать по месту клика.
- Charts и JSON sales-reports не входят в модуль и не меняют контракт.

## Ограничения

Не больше двух активных (`queued`+`running`) job на пользователя. Глобально одновременно собирается один Excel.
