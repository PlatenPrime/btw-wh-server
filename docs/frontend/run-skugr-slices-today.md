# Фронтенд: ручной scrape срезов товарной группы на сегодня

## Задача

После создания или наполнения товарной группы (`Skugr`) дать админу кнопку «Собрать срезы на сегодня» по всем SKU группы: проверить остатки/цены и при необходимости обновить уже записанные точки за текущий календарный день.

## API

- Метод/путь: `POST /api/sku-slices/skugr/:skugrId/run-today`
- Auth: JWT, роль ≥ ADMIN
- Path: `skugrId` — ObjectId группы
- Body: пустой
- Дата всегда сегодня (`Europe/Kiev`); точки перезаписываются полностью
- Полный контракт: [`docs/api/sku-slices.md`](../api/sku-slices.md)

Ответ содержит `total` / `count` / `invalid` / `errors` и `sliceDate` (YYYY-MM-DD).

## UX

### Точка входа

Карточка товарной группы / экран после `fill-skus` / создание группы. Подпись в духе «Собрать срезы на сегодня».

### Поведение

1. Кнопка доступна, когда у группы есть `skugrId` (даже при пустом `skus` — тогда `total: 0`).
2. По клику — loading на всё время запроса (синхронный HTTP, может быть долгим при большом числе SKU).
3. Пока запрос в полёте — повторный клик не слать; бэкенд вернёт 409, если второй запуск той же группы всё же ушёл.
4. После 200 — показать счётчики; предложить открыть срез konk за `sliceDate` или карточки SKU.
5. Не путать с `POST /api/slice-compensation/run` (только битые `-1` по всему konk) и с Air client-ingest.

### После ответа

| Статус | Поведение UI |
|--------|----------------|
| 200 | Toast успеха + `count`/`invalid`/`errors`; инвалидировать кэш среза konk на сегодня |
| 404 | Группа не найдена |
| 409 | Уже выполняется scrape этой группы — подождать |
| 400/401/403/500 | Стандартная обработка |

### Не делать

- Не ждать ночной cron 20:00, если нужно проверить только что созданную группу.
- Не подменять вызовом compensating slice: он не трогает валидные точки и не ограничен одной группой.
- Для Air серверный scrape здесь разрешён; client HTML-ingest остаётся отдельным каналом дозаполнения.
