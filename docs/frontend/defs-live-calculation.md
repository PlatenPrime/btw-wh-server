# Фронтенд: live-расчёт дефицитов

## Задача

Экран дефицитов должен показывать **актуальный** расчёт при открытии/refresh через один запрос. Отдельный «запуск расчёта», прогресс-бар и чтение сохранённого снимка из БД больше не используются.

## Breaking changes

| Было | Стало |
|------|--------|
| `POST /api/defs/calculate` | Удалён |
| `GET /api/defs/calculation-status` | Удалён |
| `GET /api/defs/latest` читал последний `Def` из Mongo | `GET /api/defs/latest` считает on-the-fly |
| В `data` были `_id`, `createdAt`, `updatedAt` документа Def | В `data` — `calculatedAt`, без mongo `_id` |
| Долгое ожидание + polling статуса | Один запрос (обычно секунды; loading на запросе) |

Полный контракт: [`docs/api/defs.md`](../api/defs.md).

## API

- Метод/путь: `GET /api/defs/latest`
- Auth: JWT, роль ≥ USER
- Без query/body

## UX

1. При открытии экрана — сразу `GET /latest`, показать loading на весь экран/список.
2. Не слать повторный запрос, пока предыдущий в полёте.
3. Успех — отрисовать `data.result`, totals, метку времени из `data.calculatedAt`.
4. `nameukr` приходит из складских poses (может быть пустым).
5. `existingAsk` — как раньше: кнопка/бейдж «уже есть заявка».
6. Убрать UI: кнопка «Рассчитать», прогресс, статус «идёт расчёт».

### После ответа

| Статус | Поведение UI |
|--------|----------------|
| 200 | Показать список дефицитов; пустой `result` — empty state |
| 401/403 | Стандартная обработка сессии/прав |
| 500 | Toast ошибки; предложить повторить |

### Не делать

- Не поллить `/calculation-status` — эндпоинта нет.
- Не кэшировать ответ на клиенте дольше часа без явного refresh (данные product_rests на сайте обновляются hourly; на бэке тоже TTL ~1ч).
- Не ожидать `_id` документа Def в ответе.
