# Фронтенд: ручная правка точки SkuSlice

## Задача

Дать админу форму «SKU + дата + stock/price», чтобы поправить сырую точку среза за любой календарный день (в том числе сегодня), без повторного scrape и без pack-flip apply. Типичный кейс: после TG-отчёта pack-flip вернуть масштаб витрины (`3 / 110` вместо `60 / 5.5`). Документ среза на эту дату уже должен существовать.

## API

- Метод/путь: `PATCH /api/sku-slices/sku/:skuId`
- Auth: JWT, роль ≥ ADMIN
- Path: `skuId` — MongoDB ObjectId SKU
- Body: `{ date, stock, price }` (`date` = `YYYY-MM-DD`; `stock`/`price` — finite number, `0` и `-1` ок)
- Предпросмотр текущей точки: `GET /api/sku-slices/sku/:skuId?date=`
- Поиск SKU по `perfect-14938`: `GET /api/skus?search=perfect-14938` (матчит `title` или `productId`)
- Полный контракт: [`docs/api/sku-slices.md`](../api/sku-slices.md)

Один запрос = один SKU и один день. Диапазон дат — цикл PATCH на клиенте.

## UX

### Точка входа

Карточка SKU / график остатков / строка pack-flip review (ADMIN/PRIME). Подпись в духе «Исправить срез» / «Править точку».

### Форма

1. SKU уже известен с карточки или найден через `search` по `productId`.
2. `date` — обязателен; date picker в `YYYY-MM-DD`.
3. Перед Submit — `GET` той же даты, показать текущие `stock`/`price` (или 404, если дня нет).
4. Поля `stock` и `price` — обязательны, числа.
5. Короткое пояснение: это сырая запись в `SkuSlice`, не live-scrape и не compensating slice; pack-flip следующей ночью ориентируется на эти значения.
6. После Submit — loading; повтор того же PATCH не слать, пока предыдущий в полёте.

### После ответа

| Статус | Поведение UI |
|--------|----------------|
| 200 | Показать новые `stock`/`price` и `previous`; инвалидировать кэш точки и графика за этот день |
| 400 | Ошибка валидации (`skuId` / дата / не число) |
| 404 | Toast: нет SKU или нет документа среза на эту дату (день не создаётся с нуля) |
| 401/403 | Стандартная обработка сессии/прав |
| 500 | Toast ошибки; предложить повторить позже |

### Не делать

- Не вызывать `POST /api/slice-compensation/run` вместо PATCH: compensation — повторный scrape битых `-1`, не правка масштаба.
- Не слать apply в `GET /api/sku-slices/pack-flips`: review всегда dry-run; запись — только этот PATCH.
- Не подменять live-stock (`GET /api/skus/id/:id/stock`): он не пишет срез.
- Не создавать «пустой день» на фронте ожиданием upsert документа: бэкенд 404, если среза на дату нет.
- Не слать один PATCH на весь диапазон: цикл по дням, ошибки показывать поштучно.
