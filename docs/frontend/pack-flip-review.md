# Фронтенд: проверка pack-flip скачков

## Задача

Дать админу форму «конкурент + период» и показать кратные инверсии остатка/цены в срезах SKU (сбой единицы: фасовка vs штука). Запрос **только читает** `SkuSlice`: ничего не рескейлит. Ночной cron с записью — отдельно, по конфигу auto-apply.

## API

- Метод/путь: `GET /api/sku-slices/pack-flips`
- Auth: JWT, роль ≥ ADMIN
- Query: `konkName`, `dateFrom`, `dateTo` (`YYYY-MM-DD`, `dateFrom` ≤ `dateTo`)
- Полный контракт ответов: [`docs/api/sku-slices.md`](../api/sku-slices.md)

Список конкурентов для селекта — из `GET /api/konks` (или кэш справочника). Имя можно слать в любом регистре; бэкенд нормализует. Детектор общий: любой konk допустим, не только perfect.

## UX

### Точка входа

Кнопка/пункт рядом со срезами конкурента (ADMIN/PRIME). Подпись в духе «Проверить скачки» / «Pack-flip».

### Форма

1. Выбор конкурента (`konkName`) — обязателен; без выбора Submit неактивен.
2. `dateFrom` / `dateTo` — обязательны.
3. Короткое пояснение: это диагностика масштаба pack vs piece, не продажи и не compensating scrape; срезы не меняются.
4. После Submit — loading; повтор того же запроса не слать, пока предыдущий в полёте.

### После ответа

Показать три списка (пустой список — норма, не ошибка):

- `patched` (`kind: inverse`) — кратная инверсия; для строки показать `from` и предлагаемый `patched` (не применён)
- `priceOnly` — скачок только цены, остаток в пределах ±10%
- `ambiguous` — нет однозначного возврата к одному масштабу

| Статус | Поведение UI |
|--------|----------------|
| 200 | Рендер трёх списков + `konkName` и `dates`; кэш срезов не инвалидировать |
| 400 | Ошибка валидации (`konkName` / даты / инвертированный диапазон) |
| 401/403 | Стандартная обработка сессии/прав |
| 500 | Toast ошибки; предложить повторить позже |

### Не делать

- Не слать флаг apply и не ждать записи в Mongo: эндпоинт всегда dry-run.
- Не путать с compensating slice и live-stock — другие источники и побочные эффекты.
- Не дёргать параллельно огромные диапазоны: бэкенд грузит полные `data` срезов за каждый день.
- Не трактовать пустые `patched`/`priceOnly`/`ambiguous` как 404.
