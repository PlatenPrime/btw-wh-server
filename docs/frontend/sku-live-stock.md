# Фронтенд: live остаток и цена SKU

## Задача

На карточке SKU дать кнопку «актуальный остаток / цена» (или аналог). По нажатию запросить live-данные с сайта конкурента по `url` этой карточки и показать `stock` + `price`. Это **не** срез за дату и **не** Btrade — одноразовый scrape по текущей карточке.

## API

- Метод/путь: `GET /api/skus/id/:id/stock`
- Auth: JWT, роль ≥ ADMIN
- Path: `id` — MongoDB ObjectId SKU
- Полный контракт ответов: [`docs/api/skus.md`](../api/skus.md)

## UX

### Точка входа

Кнопка на странице/карточке SKU (доступна только ADMIN/PRIME). Подпись в духе «Актуальный остаток» / «Обновить с сайта».

### Поведение

1. По Confirm/клику — loading на кнопке; повторный запрос того же SKU не слать, пока предыдущий в полёте.
2. Таймаут клиента должен учитывать scrape (секунды, иногда десятки секунд при прокси/медленном сайте).
3. Успех — показать `data.stock` и `data.price` (toast, баннер или блок на карточке). Кэш срезов инвалидировать не нужно: ответ не пишет в `SkuSlice`.

### После ответа

| Статус | Поведение UI |
|--------|----------------|
| 200 | Показать `stock` и `price` из `data` |
| 400 | Toast: невалидный id или конкурент без поддержки live-stock (`Unsupported competitor for stock`) |
| 404 | Toast: SKU нет в БД, либо товар/данные на сайте недоступны (в т.ч. внутренняя пара `-1/-1`) |
| 401/403 | Стандартная обработка сессии/прав |
| 500 | Toast ошибки сети/парсинга; предложить повторить позже |

### Не делать

- Не подменять этим запросом чтение `GET /api/sku-slices/...` — срезы и live — разные источники.
- Не трактовать 404 как «остаток ноль»: при недоступности данных бэкенд отдаёт 404, а не `{ stock: 0 }`.
- Не вызывать endpoint массово по списку SKU без явной необходимости: каждый вызов — scrape.
- Для `konkName === "air"` кнопку live-stock не показывать (или сразу вести в [air-client-sku-slices](air-client-sku-slices.md)): серверный scrape Air отключён, ответ будет 400 Unsupported competitor.
