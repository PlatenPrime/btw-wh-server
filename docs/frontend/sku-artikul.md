# Фронтенд: артикул конкурента у SKU (`artikul`)

## Задача

На карточке и в списках SKU показать код товара с сайта конкурента (лейблы «Артикул» / «Код» / reference). Это отдельное поле документа `Sku`, не путать с:

- `productId` — канонический ключ `{konk}-{rawId}` с листинга (поиск/срезы/связка);
- `btradeAnalog` — артикул аналога BTrade.

Пустое значение — норма: либо ещё не снято со страницы, либо у конкурента поля нет (sharte).

## API

Поле `artikul: string` входит в документ `Sku` во всех ответах, где возвращается карточка (список, by-skugr, get by id, create, patch). Полный контракт: [`docs/api/skus.md`](../api/skus.md).

- `POST /api/skus` — body опционально `artikul` (дефолт `""`).
- `PATCH /api/skus/id/:id` — можно задать/изменить `artikul` вручную (ADMIN).
- `GET /api/skus` и `GET /api/skus/by-skugr/:skugrId` — query `search` матчит подстроку в `title`, `productId` **или** `artikul` (регистр не важен).
- `GET /api/skus/id/:id/stock` — ответ по-прежнему только `{ stock, price }`. Побочно бэкенд может один раз заполнить пустой `artikul` с HTML страницы; в теле stock-ответа артикула нет.

## Заполнение на бэкенде (write-once)

| Источник                                           | Поведение                                                            |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| Live-stock / scrape срезов (`getSkuStockDataUtil`) | Если парсер вернул артикул и в Sku поле пустое — записывает один раз |
| Air client slice ingest (`PUT` HTML)               | То же после успешного parse HTML (важно при `AIR_IDLE_MODE`)         |
| Listing fill / skugr fill                          | Не заполняет `artikul`                                               |
| Уже непустое значение                              | Scrape/ingest **не** перезаписывает                                  |
| sharte                                             | Парсера артикула нет — остаётся `""`                                 |

Ручной create/PATCH и fix-incorrect могут менять поле без write-once ограничения.

## UX

### Список / поиск

- Колонка или вторичная подпись с `artikul`, если непустой.
- Поле поиска списка уже ходит в `search` — пользователь может искать по артикулу конкурента без отдельного фильтра.

### Карточка SKU

- Показать `artikul` рядом с названием / `productId` / `btradeAnalog`, с понятными подписями, чтобы не смешивать три «артикула».
- Если `""` — плейсхолдер в духе «не указан» / скрыть строку; для sharte не обещать автозаполнение.

### После live-stock

1. Показать `stock` / `price` как в [sku-live-stock](sku-live-stock.md).
2. Если нужен свежий `artikul` на карточке — **refetch** `GET /api/skus/id/:id` (stock-ответ артикул не отдаёт).

### Не делать

- Не подменять отображение `productId` значением `artikul`.
- Не ждать заполнения `artikul` сразу после fill товарной группы.
- Не считать пустой `artikul` ошибкой scrape.
